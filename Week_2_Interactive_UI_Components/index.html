Modal Technical Architecture

  • Focus Stacking & Trap: Uses bidirectional keyboard listeners on `Tab` / `Shift+Tab` to prevent focus from leaking into the background page while the modal is open.
  • Focus Restoration: Retains a reference to `document.activeElement` before display and safely refocuses it upon dismissal.
  • Scroll Locking Without Layout Shift: Compensates dynamically for the browser scrollbar width by measuring `window.innerWidth - document.documentElement.clientWidth`.
  • WAI-ARIA Attributes: Enforces `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, and `aria-describedby` for full screen-reader compliance.
  • Nested Dialogue Handling: Allows opening secondary confirmation dialogues on top of active modals without destroying previous focus history.

Component-Driven Architecture

NexusUI tabs are engineered strictly around W3C ARIA Authoring Practices Guide (APG) standards. The implementation uses event delegation on the tablist container to minimize memory footprint and provide flawless dynamic tab injection.

  • Sliding Glider: A single GPU-accelerated indicator uses CSS `transform: translate3d()` calculated dynamically against the active tab's bounding box.
  • Zero Layout Shifts: Responsive resize listeners via `ResizeObserver` re-anchor the indicator seamlessly upon browser window adjustments.
  • Keyboard Traversal: Left/Right arrow keys navigate cyclically across items without losing focus.

Component 03

Interactive Accordion & Disclosure System

Silky smooth collapsible panels using modern CSS Grid transitions (`grid-template-rows`), real-time live search filtering with keyword highlighting, keyboard arrow controls, and single vs. multi-expand toggle modes.

Showing all 5 accordion topics.

NexusUI uses high-performance event delegation at the root component level rather than attaching separate event listeners to every sub-element. When interactive events fire, the component identifies target actions through semantic data-* attributes. This eliminates memory leaks, minimizes event loop congestion, and ensures dynamically added items work immediately without re-binding.

Optimization: Event listeners are bound once on the container and dispatched with custom namespaced CustomEvents (nexus:accordion-toggle).

Traditional accordion animations rely on arbitrary max-height: 1000px transitions which cause timing delays, awkward pacing, and clipped contents. NexusUI leverages modern CSS Grid: 

.nexus-accordion-panel {
  display: grid;
  grid-template-rows: 0fr;
  transition: grid-template-rows 300ms cubic-bezier(0.4, 0, 0.2, 1);
}
.nexus-accordion-panel[aria-hidden="false"] {
  grid-template-rows: 1fr;
}

This guarantees pixel-perfect natural height expansion at 60 frames per second without requiring expensive JavaScript layout recalculations.

Every accordion section strictly complies with WAI-ARIA Authoring Practices:

  • aria-expanded="true/false" announces disclosure state to assistive technologies instantly.
  • aria-controls="panel-id" establishes programmatic linkage to the target collapsible content region.
  • role="region" and aria-labelledby="header-id" identify landmark boundaries for screen reader navigation.
  • Keyboard traversal: ↑ and ↓ cycle focus through accordion headers; Home and End jump to the boundary items.

The component engine includes robust defensive safeguards:

  • Defensive Initialization: Verifies DOM node existence, throwing human-readable warnings without blocking script execution if target elements are absent.
  • No-JS Fallback: If JavaScript is disabled or fails to load, CSS defaults guarantee that accordion panels and tab contents remain visible and readable.
  • Feature Detection: Gracefully polyfills `inert`, verifies `ResizeObserver`, and falls back to standard height calculation if CSS Grid transitions are unsupported.

Each component is written as an independent ES6 class with lifecycle hooks, zero third-party dependencies, and clean teardown methods (destroy()). You can import individual classes or use the automated data-* attribute initializers: 

// Declarative HTML usage:
<div class="nexus-accordion" data-nexus-accordion data-multiexpand="true">...</div>

// Programmatic JavaScript usage:
import { NexusAccordion } from './script.js';
const acc = new NexusAccordion('#myAccordion', { multiExpand: true });

class NexusModal {
  constructor(elementOrSelector, options = {}) {
    this.modal = typeof elementOrSelector === 'string' 
      ? document.querySelector(elementOrSelector) 
      : elementOrSelector;
      
    if (!this.modal) {
      console.warn(`[NexusModal] Modal element not found: ${elementOrSelector}`);
      return;
    }

    this.options = {
      closeOnEsc: true,
      closeOnBackdrop: true,
      trapFocus: true,
      onOpen: null,
      onClose: null,
      ...options
    };

    this.isOpen = false;
    this.previousActiveElement = null;
    this._handleKeydown = this._handleKeydown.bind(this);
    this._handleBackdropClick = this._handleBackdropClick.bind(this);
    this.init();
  }

  open() {
    this.previousActiveElement = document.activeElement;
    this.modal.classList.add('active');
    this.modal.setAttribute('aria-hidden', 'false');
    this.lockScroll();
    this.trapFocus();
    this.bindEvents();
    this.isOpen = true;
    this.modal.dispatchEvent(new CustomEvent('nexus:modal-opened', { bubbles: true }));
  }

  close() {
    this.modal.classList.remove('active');
    this.modal.setAttribute('aria-hidden', 'true');
    this.unlockScroll();
    this.unbindEvents();
    this.isOpen = false;
    if (this.previousActiveElement && typeof this.previousActiveElement.focus === 'function') {
      this.previousActiveElement.focus();
    }
    this.modal.dispatchEvent(new CustomEvent('nexus:modal-closed', { bubbles: true }));
  }
}

How to Evaluate & Test NexusUI:

  1. Keyboard Only Testing: Put away your mouse. Use Tab to reach any trigger button, press Enter to open. Tab repeatedly to confirm focus never escapes the modal dialog. Press Esc to close and verify focus returns to the exact trigger button.
  2. Tab System Keyboard Traversal: Focus any tab header and press ← and → arrows. In "Auto" mode, watch panels activate immediately; switch to "Manual" mode and observe that tabs require Enter or Space to activate.
  3. Live Search Filtering: Type "DOM" in the accordion search input. Notice non-matching panels hide smoothly, matching panels highlight keyword occurrences, and the ARIA status announcements update.
  4. Screen Reader Compatibility: Enable Windows Narrator (Win + Ctrl + Enter) or NVDA. Confirm appropriate announcements: "Dialog", "Tab 1 of 4, selected", "Collapsed, button".
  5. Reduced Motion Mode: Click the motion toggle icon in the header to preview compliance with users' vestibular motion sensitivities.
